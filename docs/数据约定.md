# 数据约定

`source.seed` 创建真实文件，`inventory` 暴露设备号和 inode。轮转样例允许旧文件仍有不完整尾行。压缩归档的偏移按解压后的原始字节定义；无法从文件身份或明确归档证据确认关联时，不承诺连续。

## 文件身份与路径

* 文件身份是 `(st_dev, st_ino)`，路径只用于展示。同一路径可以被 rename 后新建，也可以原地截短，二者都不靠路径或行文本判断。
* rename 轮转：旧 inode 仍在目录中（如 `gateway.log.1`）时，按身份追读到当前 EOF，读完旧文件未读尾部；活动路径上的新 inode 从字节 0 接入，作为独立逻辑流，不声明连续。
* 原地截短：同 inode 长度回退（或 mtime 变化且长度不高于已确认偏移）时，`incarnation` 加一并从 0 重读。截短后即使出现完全相同的文本，事件键也不同，不能按行文本判重。
* 身份无法确认：旧 inode 的明文与同名 `.gz` 归档都消失时，该流置为 `stopped` 并下发 `identity_lost` 缺口事件，停止而非猜测。之后活动路径出现的新文件按新流接入。

## 字节偏移与 gzip 归档

* 所有偏移都是未压缩原始字节流上的绝对偏移，事件范围为半开区间 `[start, end)`，含行尾换行符。
* gzip 的偏移定义在解压后的字节流上。接入归档前用已确认前缀的 blake2b 摘要验证：解压内容的 `[0, offset)` 摘要必须与检查点一致，未确认缓冲也要逐字节吻合；不一致则下发 `archive_unverified` 并停止。
* 归档损坏（CRC/截断/zlib 错误）下发 `archive_corrupt` 缺口，附已恢复字节数；解压总量超过 `max_archive_bytes` 下发 `archive_oversize` 并停止，明确报告未读缺口。

## 检查点与业务采纳

* 每次读取到的字节（含尚未闭合的半行、半截多字节字符）先原子写入 `checkpoint.json` 再下发事件；业务侧采纳后调用 `ack()` 才推进已确认偏移。
* 重启后未确认缓冲从已确认偏移处重新解析，以 at-least-once 方式重放，事件的来源身份与字节范围保持不变。UTF-8 使用 strict 解码，绝不产生替代字符。
* 下游去重应使用 `follower.event_key`：`(origin_identity, incarnation, start, end)`，而不是记录文本。

## 损坏与资源上限

* 非法 UTF-8 或非法 JSON 的闭合行下发 `corrupt` 事件，保留 `raw_hex` 原始字节与字节位置，不阻挡后续合法行。
* 单行超过 `max_line_bytes`：未闭合行进入排空模式，只保留 256 字节前缀证据，读到行尾后下发 `line_too_long` 缺口；闭合超长行在解析处直接转缺口。其后的合法行照常交付。
